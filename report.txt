FlipFocus: Project Report

1. ABSTRACT
In the modern academic and professional environment, time management and maintaining deep focus are critical challenges. Traditional methods of productivity tracking often rely on manual logging, which can be inconsistent or disruptive to the flow of work. FlipFocus is an IoT-based productivity solution designed to bridge this gap by providing an automated, real-time focus tracking system.

The core of FlipFocus is a hardware device equipped with an ESP32 and an MPU6050 sensor that detects orientation to log different work profiles (e.g., Assignment, Exam Prep, Core Coding, and Breaks). This data is seamlessly synced with a Firebase Real-Time Database and visualized through a fluid, responsive web dashboard. Our main objective is to assist students and professionals who struggle with focus fragmentation or need an empirical way to analyze their productivity patterns. 

This web application offers a modern, high-performance interface featuring a circular donut chart and a rotating profile wheel that provides immediate visual feedback. By automating the data logging process, FlipFocus allows users to gain insights into their performance without the time-wasting formalities of manual entry. This system is designed for ease of use, enabling users to effortlessly monitor their "Deep Work" sessions and optimize their daily schedules for better efficiency.

CHAPTER-1: INTRODUCTION

1.1 MOTIVATION
In an era dominated by digital notifications and fragmented attention, the ability to engage in "Deep Work" has become a competitive advantage. However, most productivity tools are software-based (apps/websites), which often become sources of distraction themselves. FlipFocus was motivated by the need for a physical, tangible interface that anchors the user's intention without requiring them to touch their phone or computer.

1.2 PROBLEM STATEMENT
Manual time-tracking is often neglected because it adds cognitive load. Existing solutions either require high manual effort or are too passive to influence behavior. There is a lack of low-cost, automated systems that provide both physical interaction and high-quality digital visualization for student productivity.

1.3 OBJECTIVES
- To design a hardware device that detects work modes through physical orientation.
- To implement a real-time data pipeline using Firebase for zero-latency tracking.
- To develop a modern, "Blueprint" aesthetic web dashboard that provides immediate visual motivation through a rotating profile wheel and donut chart.

CHAPTER-2: SOFTWARE REQUIREMENTS SPECIFICATION

In the current academic environment, maintaining sustained focus is difficult due to constant digital distractions. Students often find it challenging to manually log their study hours, leading to a lack of empirical data on their own productivity. FlipFocus addresses this by automating the time-tracking process through an intuitive hardware-software ecosystem.

2.1 FUNCTIONAL REQUIREMENTS
The system must autonomously detect the user's work mode and provide immediate, accurate visualization of productivity data.

2.1.1 USER CLASS: PRODUCTIVITY USER
R.1: Orientation-Based Mode Detection
Description: The system uses an MPU6050 accelerometer to detect the physical orientation of the device. Each of the four sides represents a specific work profile.
- R1.1: Detect gravity vectors (X, Y, Z).
- R1.2: Assign active zone based on the dominant vector (> 9.5 m/s²).
- R1.3: Trigger a status update to the cloud.

R.2: Cloud Data Synchronization
Description: The ESP32 microcontroller must maintain a stable WiFi connection to sync local timers with the Firebase Real-Time Database.
- R2.1: Securely connect to the Firebase RTDB.
- R2.2: Increment time counters for the active profile every second.
- R2.3: Ensure data persistence across sessions.

R.3: Real-Time Dynamic Dashboard
Description: The web interface must reflect the current state of the hardware in real-time.
- R3.1: Visualize productivity distribution via a dynamic Donut Chart.
- R3.2: Rotate the profile wheel to highlight the active session.
- R3.3: Display total accumulated time for each profile.

2.2 NON-FUNCTIONAL REQUIREMENTS
- Usability: The dashboard must be fully responsive, providing a robust experience on both desktop and mobile devices.
- Performance: The synchronization latency between the hardware orientation change and the web dashboard update should be less than 2 seconds.
- Reliability: The system should accurately distinguish between deliberate orientation changes and accidental movements.

2.3 SYSTEM REQUIREMENTS
- Hardware: ESP32 Microcontroller, MPU6050 Gyro/Accel Sensor, 5V Power Supply.
- Software Environments: Arduino IDE (Firmware), Firebase (Backend), VS Code (Web Development).
- Libraries: Chart.js (Visualization), Firebase-ESP-Client (Connectivity).

CHAPTER-3: SYSTEM DESIGN & ARCHITECTURE

3.1 HARDWARE ARCHITECTURE
The system consists of an ESP32 microcontroller interfaced with an MPU6050 Inertial Measurement Unit (IMU). 
- ESP32: Handles WiFi connectivity and data transmission.
- MPU6050: Measures 3-axis acceleration to determine which side of the device is facing up.

3.2 SOFTWARE ARCHITECTURE
The software stack follows a Producer-Consumer pattern:
1. Producer (Firmware): ESP32 reads sensor data, determines the active profile, and pushes updates to Firebase.
2. Middleware (Firebase): Acts as a real-time bridge, storing the state and accumulated seconds for each profile.
3. Consumer (Web Dashboard): A single-page application that listens to Firebase and updates the UI (Chart.js and CSS animations) dynamically.

3.3 UI/UX DESIGN PHILOSOPHY
The dashboard is designed as a "Productivity Compass." The rotating wheel ensures that the active task is always at the top, mimicking a physical dial. The use of a high-contrast "Blueprint" color palette (Sky Blue, Emerald, Slate) reduces eye strain while maintaining a professional look.

CHAPTER-4: IMPLEMENTATION & METHODOLOGY

4.1 FIRMWARE LOGIC
The ESP32 runs a non-blocking loop that checks the Z, Y, and X gravity vectors. If a vector exceeds 9.5 m/s², the system identifies that specific side as "Up." A debouncing timer is implemented to prevent accidental triggers during movement.

4.2 WEB DEVELOPMENT
The dashboard uses:
- Chart.js: For the responsive donut visualization.
- CSS3 Transitions: For the 1.2s bouncy rotation of the profile wheel.
- Firebase JS SDK: For real-time, event-driven UI updates.

CHAPTER-5: CONCLUSION & FUTURE SCOPE

5.1 CONCLUSION
The FlipFocus prototype successfully demonstrates that a physical-first approach to productivity tracking is both feasible and effective. The seamless integration between the hardware orientation and the digital dashboard provides a frictionless user experience that encourages sustained focus.

5.2 FUTURE SCOPE
- Haptic Feedback: Adding a vibration motor to alert the user when a session exceeds a certain time.
- Pomodoro Integration: Building a Pomodoro timer directly into the hardware logic.
- Mobile Application: Developing a native Flutter or React Native app for on-the-go tracking.
- Data Analytics: Implementing weekly and monthly trends to provide deeper insights into productivity habits.
